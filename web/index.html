Ask a question about 35 Wikipedia articles. The page finds the best passages with keyword search (BM25) and meaning search (bge-small embeddings), reranks them with a cross-encoder, and picks the answer sentence. Everything runs in your browser: no server, nothing you type is sent anywhere.

How it works

  • Passages: each article is split into paragraphs (1,212 in total).
  • Hybrid retrieval: BM25 and bge-small embeddings each rank every paragraph; reciprocal rank fusion merges the two lists into 20 candidates.
  • Reranking: a MiniLM cross-encoder reads the question together with each candidate and rescores them.
  • Answer: the extractive reader returns the sentence from the top 3 passages that shares the most words with the question.
  • Guardrails: questions and passages that look like prompt injection are blocked, and answers not supported by the passages are withheld.

How close is this to the real system?

This page is a JavaScript port of the Python pipeline, using 8-bit versions of the same two models.

  • The full system can also answer with the small LLM Qwen3-0.6B. That model is too big to run on a phone, so this page shows the extractive answer only. The server version with the LLM is in the repo.
  • SQuAD 2.0 also has "trick" questions with no answer in the article (one is always among the examples). Like the extractive baseline in the evaluation, this page does not detect them, so it still returns a sentence.
